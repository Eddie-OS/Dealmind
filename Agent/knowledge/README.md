# knowledge/ · 手册之外的补充知识

往这里丢 `.md` / `.txt`，销冠每一轮会按关键词检索它们，
命中的片段会注入 prompt，同时作为 `08_content_guard` 的证据源
（写在这里的数字不会被当成编造改掉）。

## 什么该放这里

- 售后政策、以旧换新规则、分期方案这类**手册不会写但客户一定会问**的内容
- 竞品的公开参数对比
- 门店活动、优惠有效期

## 什么不该放这里

- 产品本身的卖点参数 —— 那些应该走 `inbox/` 让 `01_handbook_ingest` 结构化，
  结构化之后销冠是"按剧本讲"，放这里只是"检索到了顺嘴提一句"，效果差很多。

## 检索方式

关键词检索，不是向量检索。三项加权打分：中文二元组重合、英文词重合、
数字重合（数字权重最高，因为价格和参数最该被精确召回）。

这意味着**没有语义泛化**：客户说"续航不行"检索不到只写了"电池容量"的段落。
写文档时把同义说法一并写进去，比如标题写「续航 / 电池」。

好处是不需要 embedding 模型，不用下载模型文件，整个目录可以离线跑。

## 组织建议

用 markdown 标题分节，检索命中时会带上小节名，方便回溯来源：

```markdown
# 售后政策

## 保修范围
整机保修 12 个月，屏幕单独 6 个月……

## 以旧换新
支持同品牌折抵……
```
