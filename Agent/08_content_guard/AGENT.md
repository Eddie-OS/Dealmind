# 08 · 事实护栏 Agent

销冠说出口之前的最后一道闸。销冠**每一轮**都要过它，不可关闭。

## 它解决什么问题

销售模型有个稳定的坏习惯：编具体数字。"续航 18 小时"、"比竞品快 2ms"、
"现在下单立减 800" —— 听起来专业，但手册里根本没有。
这类内容进了优秀话术库，一线照着讲出去就是事故。

## 判定依据（证据源，按强度排序）

| 证据源 | 来自 |
|--------|------|
| 产品手册全文 | `01_handbook_ingest`，**最强证据** |
| 产品事实卡 | 会话启动时抽取的型号/参数/价格区间 |
| 知识库命中片段 | `knowledge/` 的关键词检索结果 |
| 本轮工具返回 | Agent 侧默认关闭工具，恒为空 |

一个具体数字/型号只要在上述任一证据源里找得到，就放行；
全都找不到，改写成模糊表述（典型："具体数字我现场帮您在官网确认"）。

## 输出

不产生独立事件，结果写进销冠 `turn.metadata.content_guard`：

```json
{ "rewritten": true, "warnings": ["未证实 claim: '2ms' → 已改写"] }
```

## 落盘

`runs/<run_id>/sessions/<persona_id>/steps/08_content_guard/NNN_r<轮次>.md`
**只在实际发生改写时写文件**。没有改写就没有文件，
所以这个目录的文件数直接就是本场的"编造次数"。

`10_quality_analyst` 把这个次数作为质量扣分项。

## 已知失败模式

手册解析得不完整时，护栏会把手册里本来写了、但没被抽取出来的数字
当成编造改掉，销冠话术会变得空洞。出现这种情况先去看
`01_handbook/handbook.md` 是不是漏抽了参数表。

## 单独运行

```bash
python 08_content_guard/run.py --text "这款续航 18 小时，比 iPad 快 2ms。"
```
